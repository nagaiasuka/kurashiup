# 記事コンテンツのGit管理

記事本文・比較データ・アフィリエイトリンク・商品画像・アイキャッチ・生成スクリプトを、このディレクトリで管理する。

`review-guides/<記事スラッグ>/` を記事ごとの保存先とする。更新は生成元に反映し、生成物の表示とリンクを確認してからコミット・プッシュする。

`.github/workflows/deploy.yml` は `scripts/package-guide-release.py` で承認済みのウォッチ記事をテーマ配信用に梱包する。本番テーマの `inc/guide-release.php` が、全ファイルのSHA-256検証後に記事とアイキャッチを一度だけ登録・公開する。対象は `running-watch-8-compare` の新規記事のみ。既存記事が同じスラッグを使っている場合は上書きしない。外部から投稿内容を送信するAPIは設けない。

商品画像はGit配信したテーマ内のリリースディレクトリを参照し、アイキャッチはWordPressメディアへ登録する。完了状態は `kurashiup_release_running-watch-20261111` オプションに投稿IDとして保存する。失敗時は下書きのまま保持し、同名の `_error` オプションとPHPログへ原因を記録する。通常の失敗は5分後に再試行する。プロセスが強制終了してロックが残った場合は、実行中の処理がないことを確認して管理者が `_lock` オプションを削除する。

このリリースは一度限り。公開後のGit変更だけでは記事を再更新しない。今後の記事追加・改訂は承認対象とリリースIDを明示して実装する。

公開した記事は、各記事の `公開準備.json` に公開URL・投稿ID・アイキャッチのメディアIDと確認結果を記録する。未公開のものを公開済みとして記録しない。認証情報はGitに保存しない。
